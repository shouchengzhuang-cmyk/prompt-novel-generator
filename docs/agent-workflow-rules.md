# Agent 协作规则

## 一、角色分工

用户：只负责提出目标、做最终取舍，不负责反复解释技术细节。

GPT：负责把用户想法整理成设计文档、短任务单、验收标准。不得一次性输出过长指令。

CC：负责执行明确的小范围代码修改。每次任务必须说明修改文件、修改点、是否影响逻辑。

Codex：负责验收、排查、保守修复。优先检查风险，不负责扩大需求。

## 二、任务规则

1. 每次只做一个小目标。
2. 没有写入 docs 的大想法，不直接进入代码。
3. CC 不允许自行扩大范围。
4. Codex 主要负责验收，不频繁参与创意设计。
5. GPT 输出给 CC 的指令必须短、明确、可复制。
6. 如果需求没谈妥，先写“设计备忘”，不写代码任务。

## 三、每次任务必须包含

- 目标
- 修改范围
- 禁止修改范围
- 验收标准
- 回报格式

## 四、回报格式

1. 修改了哪些文件
2. 每个文件改了什么
3. 是否影响原有功能
4. 如何测试
5. 是否已提交
