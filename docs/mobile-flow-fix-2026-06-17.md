# 小墨匣移动端主路径修正收口记录

日期：2026-06-17

关联提交：`eacb599 feat: refine mobile writing and reading flow`

## 1. 背景

用户基于移动端实际使用手写反馈，指出小墨匣移动端在“继续写作”“继续阅读”“章节目录”“编辑设定”“管理素材”等入口之间路径不够清楚。

原体验中，首页、写作页、阅读页、项目设置页之间的入口语义有重叠：用户不容易判断一个按钮是进入下一章生成、打开最近阅读章节、进入章节目录，还是编辑项目设定。

## 2. 本轮目标

- 修正移动端首页到阅读 / 写作 / 目录 / 设定 / 素材的主路径。
- 不改生成接口。
- 不改流式输出。
- 不改 `chapters` / `variants` 数据结构。
- 不影响素材池现有逻辑。

## 3. 修改摘要

本轮提交 `eacb599` 涉及 6 个文件：

- `src/App.jsx`
- `src/apps/MobileApp.jsx`
- `src/pages/HomePage.jsx`
- `src/pages/mobile/MobileProjectPage.jsx`
- `src/pages/mobile/MobileWritingPage.jsx`
- `src/styles/mobile.css`

主要改动：

- 首页当前项目卡保留“继续写作”，新增“继续阅读”。
- 首页快捷入口将重复的“写作”弱化为“章节目录”。
- 继续阅读优先打开最近章节，无法判断最近章节时进入目录。
- 继续写作进入下一章生成页，并展示项目名、目标章节、承接章节。
- 生成页增加“查看上一章”“返回目录”，保留“返回阅读页”。
- 写作输入附近增加可折叠“写作参考提示”，只展示已有摘要 / 编辑记忆 / 上一章信息，不写入用户输入框。
- 移动端项目设置页改为折叠卡片入口，避免一屏堆多个巨大 textarea。
- 项目编辑记忆说明改为：记录长期写作判断、伏笔跟踪、人物关系演变和后续写作风险；不同于剧情摘要。
- Toast 移动端位置调整到底部导航上方，并兼容 `safe-area-inset-bottom`。

## 4. 修复的路径问题

提交前验收中发现并修复了 3 个问题：

1. 继续写作后“查看上一章 / 返回阅读页”初始不可用。
   - 原因：从首页进入续写页时没有先加载承接章节。
   - 修复：进入续写页时读取最近章节，使“查看上一章”和“返回阅读页”有可用目标。

2. 首页“素材库”入口仍提示开发中。
   - 原因：移动端快捷入口仍保留旧的开发中提示。
   - 修复：改为打开当前项目的“素材与备份”面板，不新增素材接口，不改素材池数据结构。

3. “世界观 / 人物卡”在某些状态下只进入目录，不展开对应设定卡。
   - 原因：移动端快捷动作在项目刚加载后读取的 `projectDetails` 可能还不是目标项目详情。
   - 修复：优先使用当前项目详情，否则读取缓存详情后再打开对应设定卡。
