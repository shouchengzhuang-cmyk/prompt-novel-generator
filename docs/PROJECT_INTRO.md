# 小墨匣 项目介绍

## 1. 项目定位

小墨匣是一个面向个人写作的轻量工具。它的核心目标是把日常记录、零散想法、人物片段、剧情素材快速改写成小说化文本。

它不是复杂的小说工业化管理平台，而是一个「打开就能写、写完能保存、能反复重写」的个人创作工具。用户不需要学习项目管理方法论，不需要理解版本控制概念，只需关注一件事：把脑子里想写的东西写出来。

整个工具的交互围绕「生成→阅读→重写」这个循环展开，而非围绕「任务→审稿→发布」的管理流程。

## 2. 核心使用流程

1. **创建项目** — 在书架页点击「创建新项目」，输入项目名称
2. **填写设定** — 可选填写世界观、人物设定、写作规则、剧情摘要，这些设定会在生成时作为上下文注入
3. **输入生成需求** — 写下当前想写的方向或素材（例如「主角在雨夜发现一封信」）
4. **生成章节** — 点击生成，AI 根据设定和需求输出章节正文
5. **阅读章节** — 生成完成后直接在阅读区查看，支持切换背景主题和字号
6. **重写本章** — 对同一章节输入不同的改写要求，生成候选版本
7. **候选版本管理** — 候选版本保存在列表中，可预览正文，可选择「沿此版本继续」
8. **编辑正文** — 在移动端可直接编辑本章标题和正文，保存后自动备份原文
9. **导出** — 支持导出全文（Markdown）、导出项目备份（ZIP）

## 3. 当前主要功能

- **项目书架** — 所有项目以卡片形式展示，支持创建和删除
- **项目设定管理** — 世界观、人物、写作规则、剧情摘要、编辑记忆，均可在界面中编辑保存
- **章节生成** — 基于 DeepSeek API 生成章节正文，支持快速模式（v4-flash）和深度模式（v4-pro）
- **流式输出** — 生成和重写过程中，正文实时逐段显示，用户无需等待接口全部返回
- **章节阅读** — 阅读区支持白/米黄/浅灰/夜间四种背景主题，支持小/中/大字号切换
- **章节重写与候选版本** — 对已有章节输入改写要求，生成多个候选版本，可预览和切换当前主线
- **移动端返回层级适配** — 手机侧滑和浏览器物理返回键遵循「编辑器→阅读页→项目页→书架」的内部层级
- **移动端简单编辑本文** — 移动端可内联编辑章节标题和正文，保存时自动保留原文作为版本备份
- **全文导出** — 导出为 Markdown 文件
- **备份导出** — 导出为 ZIP 压缩包，包含项目全部设定和章节
- **章节规划** — 支持 JSON 格式的章节大纲编辑（桌面端可见，移动端入口已隐藏）

## 4. 移动端体验优化

近期优化方向集中在让移动端主链路更干净：

- 手机侧滑 / 浏览器物理返回不再直接退出应用，而是按照「阅读页 → 项目页 → 书架」的层级逐级返回
- 书架页阻止误退出：在书架根层级时 push 一个历史守卫状态，防止一次返回就离开应用
- 隐藏移动端章节规划入口，避免干扰「书架 → 项目 → 阅读 → 生成/重写」的主链路
- 隐藏完整编辑室（备注、AI 备注生成、编辑对话），改为轻量的「编辑本文」内联面板，只做标题+正文修改+保存
- 重写本章改为流式输出，实时显示生成内容，不依赖接口全部返回后再展示

## 5. 技术栈

| 层 | 技术 |
|---|---|
| 前端框架 | React (Hooks + JSX) |
| 构建工具 | Vite |
| 后端运行时 | Node.js |
| 后端框架 | Express |
| AI 接口 | DeepSeek API（v4-flash / v4-pro） |
| 数据存储 | 本地文件系统（novels/ 目录） |
| 部署 | PM2 进程管理，可配合 Nginx 反向代理 |

项目未使用数据库，未使用容器化方案，未引入 ORM 或 ODM。前端与后端通过 REST API 通信，流式生成使用 Server-Sent Events。

## 6. 数据存储方式

所有项目数据以文件形式存储在服务器本地 `novels/` 目录下，每个项目一个子目录：

```
novels/
  <项目名>/
    world.md           世界观设定
    characters.md       人物设定
    style.md            写作规则
    summary.md          剧情摘要
    editorial-memory.md 编辑记忆
    chapters/
      index.json        章节索引（标题、创建时间、版本列表）
      001.txt           章节正文
      002.txt
      ...
      variants/
        <文件名>.json   候选版本数据
```

不依赖外部数据库，数据即文件。迁移或备份时直接复制 `novels/` 目录即可。导出备份使用 ZIP 格式打包。

## 7. 适合的使用场景

- **日记改写小说** — 把日常记录当作素材，让 AI 改写成连贯的小说段落
- **生活片段扩写** — 记录一个场景或对话，扩展为完整的文学化文本
- **快速生成章节草稿** — 有设定和大纲后，快速生成章节初稿
- **同一章节的多版本比较** — 输入不同的改写要求，生成多个候选版本对比
- **手机端随时查看和轻量修改** — 通勤或碎片时间阅读章节、修正错字、调整段落

## 8. 当前设计原则

- **优先顺手，而不是堆功能** — 每个功能都要回答：用户走到这里时，ta 真正想做什么
- **优先移动端真实体验** — 移动端是主要使用场景，功能取舍以手机上的实际操作为准
- **优先稳定保存和可回退** — 生成内容即时写入文件，重写前原文自动备份为变体，不丢失
- **功能可以保留，但入口不应干扰主链路** — 章节规划、编辑室等功能代码完整保留，但移动端入口隐藏，待主链路打磨成熟后再考虑展示
- **复杂功能先隐藏，核心流程先打磨** — 先让「生成 → 阅读 → 重写」这条线在手机上顺畅跑通，再考虑扩展

## 9. 后续可优化方向

- **更稳定的流式生成状态提示** — 在网络波动或接口超时场景下，给用户更清晰的反馈和恢复路径
- **候选版本对比体验** — 当前只能分别预览，缺少并排或差异对比能力
- **更好的章节搜索** — 项目章节增多后，目前仅依文件名排序，缺少全文搜索或关键词定位
- **更安全的数据备份** — 当前备份依赖手动导出，可增加定时自动备份或云存储选项
- **更清晰的移动端按钮层级** — 阅读页底部操作按钮逐步增多，需要重新组织避免视觉拥挤
- **项目级导入 / 导出优化** — 当前导出为单向操作，缺少项目导入重建能力
