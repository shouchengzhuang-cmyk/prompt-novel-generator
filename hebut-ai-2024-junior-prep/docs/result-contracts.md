# 课程实验“最终结果合同”

## 什么叫结果合同

结果合同不是老师题目的替代品，而是一份机器可检查的交付清单：这次实验最终必须留下哪些表、图、日志、截图和数字。收到正式要求后，应先修改合同，再让 Codex 写代码。

机器可读版本位于 [`../reporting/contracts.json`](../reporting/contracts.json)。本文件解释为什么要这些产物，以及报告中怎么使用。

## 统一最低要求

无论哪门课，一次可提交实验至少应包含：

- 老师原始要求和数据说明；
- 环境、依赖版本、随机种子和实际运行命令；
- 原始数据只读，处理结果另存；
- 核心指标表；
- 至少一个失败样例或局限；
- 逐样本/逐迭代/逐参数的机器可读结果；
- 图表原文件，不只保留截图；
- 每条主要结论引用证据 ID；
- Git commit 或等价版本标识。

## 数据挖掘

### 实验一：数据预处理

高置信度历史题型。最终应生成：

1. `cleaning_summary.csv`：缺失日期、负数数量、日期格式、冗余字段、重复记录等各处理项的数量；
2. `before_after_samples.csv`：处理前后代表样例；
3. `cleaned.csv`：最终清洗数据；
4. K-means 异常检测图；
5. PCA 方差贡献图；
6. 处理前后行数、缺失率和异常数；
7. 一段解释：为什么某条记录被修正或删除，以及处理可能带来的偏差。

报告核心不是贴一屏代码，而是证明“数据发生了什么变化”。

### 实验二：数据立方体与 OLAP

高置信度历史题型。最终应生成：

- 1019、1020、1021 三个商店的展开表；
- 商品类别 × 日期 × 商店的可查询数据结构；
- 老师指定查询的输入、筛选条件和结果；
- 至少一个自定义查询；
- 聚合口径说明：求和字段、缺失组合如何处理、日期范围；
- 导出的 cube CSV/JSON，避免结果只存在于控制台。

报告应逐条回答查询，而不是只说“实现了 OLAP”。

### 实验三：Apriori

高置信度历史题型。最终应生成：

- 交易篮子数量和平均篮子长度；
- 最小支持度；
- L1、L2、L3……各阶频繁项集及支持度；
- 候选集数量随阶数变化；
- 不同商店或不同支持度的对比；
- 交易篮子和频繁项集 CSV；
- 解释一个有业务含义的商品组合，同时提醒“频繁共现不等于因果”。

### 实验四：贝叶斯分类

中高置信度历史序列。最终应生成：

- 数据划分和类别分布；
- Accuracy、Precision、Recall、Macro-F1；
- 混淆矩阵；
- 分类报告；
- 逐样本预测；
- 典型错误样例与可能原因。

### 实验五：K-means

中高置信度历史序列。最终应生成：

- 不同 K 的 SSE/惯性；
- 肘部法曲线；
- 轮廓系数；
- 聚类中心；
- 样本簇标签；
- 二维投影或特征空间聚类图；
- 解释聚类标签没有天然语义，簇编号也无大小顺序。

## 缺失数据填补与下游验证

这是近届河工大公开实验中非常典型的“结果密集型”结构，课程归属仍需当届核对。

建议自动完成：

- 20%、40%、60% 缺失率；
- 均值、KNN、自编码器填补；
- LR、SVM、RF、MLP 下游验证；
- Precision、Recall、F1、nF1；
- 三张完整矩阵；
- F1 柱状图、nF1 热力图、稳定性折线；
- 可选雷达图、棒棒糖图；
- 每种填补数据 CSV；
- 最优方法随缺失率变化的结论与局限。

这一类作业最应由脚本自动跑批，禁止手工复制数字。

## 计算机视觉

### 实验一：车道线检测

2026 公开实验高度具体。最终应生成：

- 实际处理图片数量；
- BDD100K/KITTI 数据来源和选样规则；
- 4 组完整参数表；
- 每张图每组参数的输出索引；
- 六联图：原图、灰度、Canny、ROI mask、ROI edge、最终检测；
- 一张代表性四参数对比图；
- 失败场景：阴影、弯道、夜间、遮挡、道路标线缺失；
- 可选视频输出和帧率；
- 对 Canny/Hough/ROI 参数影响的文字解释。

历史目录名出现“5 张图 × 4 组参数”，但当届数量必须以老师要求为准。

### 实验二：CIFAR-10 传统方法与 CNN

最终应生成：

- HOG+SVM、颜色直方图+KNN、组合特征+SVM 的 Accuracy/Macro-F1；
- 传统方法混淆矩阵；
- 传统方法对比图；
- CNN 每轮训练损失；
- CNN 测试 Accuracy/Macro-F1；
- CNN 混淆矩阵；
- 至少 6 个错误样例；
- 传统方法与 CNN 的统一总表；
- 训练耗时、推理耗时和参数量；
- 哪些类别最容易混淆及原因。

## 深度学习

### 实验一：自动求导与梯度截断

最终应生成：

- 输入、解析梯度、自动梯度对照表；
- 最大绝对误差；
- 截断前梯度范数；
- 截断后梯度范数；
- 完整控制台日志；
- 说明 `backward()` 累积梯度与清零行为。

### 实验二：FNN 多任务

最终应生成：

- 回归、二分类、多分类数据分布图；
- 手动 FNN 与 `torch.nn` 的结构、损失和指标对比；
- 激活函数对比曲线；
- 学习率对比曲线；
- K 折逐折结果、均值和标准差；
- 回归 MSE、二分类 Accuracy、多分类 Accuracy；
- 至少一个不收敛或性能较差的设置；
- 对结果稳定性和随机种子的说明。

## 自然语言处理候选题型

### 中文情感分类

正式课程归属尚待核对，但近届公开实验的结果形态很清楚：

- 按学号采样的数据索引；
- 类别分布；
- 学习率、批大小、轮数参数扫描；
- 每组耗时、验证准确率、测试准确率；
- 最优模型不是只按测试集挑选，应说明选择规则；
- 分类报告、混淆矩阵、错误样例；
- 训练日志、权重清单和预测 CSV；
- 类别不均衡影响分析。

### KG + 向量 RAG

候选交付：

- 教师提供与学生补充的三元组、文档数量；
- 每条新增材料的来源；
- 纯 LLM、向量 RAG、KG+向量 RAG 逐题对照；
- 有标准答案的准确率或人工评分准则；
- 无法回答问题和幻觉案例；
- 架构图、知识图谱 HTML/截图；
- 原始回答 JSON/CSV，不能只留最终挑选后的答案。

## 机器学习系统与平台实践

高置信度同名课程项目。最终应生成：

- MLP、CNN、RNN/LSTM 参数量；
- 三模型训练/测试损失和准确率；
- 三模型统一比较表；
- 最佳模型混淆矩阵；
- t-SNE 或等价特征可视化；
- 权重文件、SHA-256 和配置清单；
- 推理 API 请求/响应样例；
- API 延迟；
- 前端手写画板截图；
- 失败手写样例；
- 从零启动、训练、启动后端和打开前端的完整命令。

## 低置信度课程的通用结果要求

### 机器学习与模式识别

至少保留：模型统一对比表、Accuracy/Macro-F1、混淆矩阵、决策边界或降维图、错误样例、逐样本预测。

### 计算智能

至少保留：多随机种子结果、均值/标准差、最优/最差、收敛曲线、原始运行 CSV。单次“看起来很优”的结果不够。

### 数值分析与优化

至少保留：逐步迭代表、最终误差、迭代次数、收敛曲线、停止条件、理论值或高精度参考值。

### 软件设计与编程实践

至少保留：需求追踪矩阵、系统架构图、自动测试汇总、关键功能截图、部署/演示命令、已知缺陷与答辩提纲。

## 报告写作顺序

未来 GPT 必须按以下顺序工作：

1. 提取正式评分点；
2. 修改结果合同；
3. 运行并产出全部文件；
4. 审计清单；
5. 从结果中提炼结论；
6. 最后才生成报告文字；
7. 再映射到教师 Word 模板。

反过来先写结论再补数字，极易制造漂亮但不可验证的“实验色情片”：画面很刺激，数据全是演的。
