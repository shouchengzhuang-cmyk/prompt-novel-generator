## 3. 学校特异性证据：按可靠性排序

### A. 数据挖掘：历届五实验序列

公开的河工大历届材料已经锁定：

1. 数据预处理；
2. 商品类别 × 商店 × 日期三维数据立方体与 OLAP；
3. Apriori 频繁项集；
4. 贝叶斯决策/朴素贝叶斯分类；
5. K-means 聚类。

前三个实验的题目字段和报告章节较具体：

- 实验一会处理缺失日期、负数数量、日期格式、冗余字段和购物篮商品序列；公开材料还展示 K-means 异常检测、PCA 贡献图和最终清洗 CSV；
- 实验二常见商店编号 `1019/1020/1021`，商品类别 `10010/10020/10030/10088`，日期 13-19 日，并要求若干指定 OLAP 查询；
- 实验三按同一流水号构造交易篮子，设置最小支持度，输出各阶频繁项集。

判断：题型命中率高，但正式数据文件、字段名、算法限制和报告模板仍可能变化。

## 4. 用户真正想省下的时间

按用户过往经验，最耗精力的通常不是单个算法函数，而是：

- 老师要求里到底要哪几张图、哪张最终表；
- 跑多个参数组合并整理成统一矩阵；
- 截图、重命名、排序和插入报告；
- 给每个数字找来源；
- 写结果分析、失败样例和结论；
- 将内容塞进老师给的 Word 模板；
- 临交前检查缺图、路径、学号、指标定义和答辩问题。

因此本仓库的长期主线应是：

> **先锁定结果合同，再运行；先完成证据清单，再写报告。**

## 5. 新作业标准处理流程

### 第一步：原样保存老师材料

新建独立目录，将通知、附件、模板、数据说明和评分点放进 `teacher/`。不要先改名、重排或摘要到丢失细节。

### 第二步：选择或新建结果合同

在 `reporting/contracts.json` 找最接近的合同。若当届要求不同：

- 复制为新合同；
- 标注当届课程、日期和教师要求来源；
- 删除不需要的历史产物；
- 增加本届明确要求的结果；
- 不要强行复用旧合同。

### 第三步：初始化工作目录

```bash
python scripts/init_assignment.py \
  --course "课程名" \
  --experiment "实验名" \
  --contract 合同ID \
  --output work/目录名
```

### 第四步：先生成结果，不先写作文

代码应把所有输出写入 `artifacts/`：

- `metrics.json`；
- 参数扫描 CSV；
- 逐样本预测 CSV；
- 图表 PNG/SVG；
- 完整日志；
- 环境和随机种子；
- 模型权重校验清单；
- 需要人工截图的页面清单。

### 第五步：填写并审计清单

```bash
python reporting/audit_artifacts.py work/.../result-manifest.json
```

错误清零后才能写报告；警告必须逐条核验。

### 第六步：生成报告草稿

```bash
python reporting/build_report.py \
  work/.../result-manifest.json \
  --output work/.../实验报告草稿.md \
  --allow-warnings
```

### 第七步：映射到教师模板

收到指定 DOCX 后，再把已核验的 Markdown 内容映射进去。只改格式，不重新发明指标或结论。

### 第八步：助教式验收

- 随机抽查 5 个数字能否追溯；
- 检查训练集/测试集混用和数据泄漏；
- 检查所有图表坐标、图例、单位、标题；
- 检查报告中的文件名与实际产物一致；
- 生成 10 个答辩问题；
- 标出本人必须能解释的 5 个核心点。

- 为了让报告好看而删除失败样例；
- 用绝对路径、未固定随机种子或不可复现的手工步骤交差；
- 未经用户授权合并 Draft PR 或改动原项目。

## 7. 未来 GPT 的交付标准

一次作业完成时，至少应留下：

1. 老师原始要求；
2. 要求差异表；
3. 可复现代码与环境；
4. 结构化结果清单；
5. 合同审计通过记录；
6. 完整表格、图像、日志和截图；
7. 报告草稿；
8. 最终模板版报告；
9. 口头答辩速记；
10. 未确定事项与本人待办。

做到这些，未来模型即便更换、套餐降级或上下文丢失，也能从仓库继续，而不是重新考古一遍。
