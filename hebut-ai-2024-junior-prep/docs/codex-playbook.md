# Codex 适配手册

## 第一阶段：收到作业当天

把老师的原始通知、附件和数据放进独立分支，然后使用：

```text
你正在适配河北工业大学人工智能专业的一次正式课程实验。

必须先完成差异分析，禁止直接生成最终报告：
1. 阅读老师原始要求、评分点、数据说明和模板；
2. 阅读 hebut-ai-2024-junior-prep/docs/evidence-matrix.md；
3. 列出正式要求与现有预制代码在输入、算法、输出、依赖、指标、报告结构上的差异；
4. 标明哪些内容必须手写、哪些库被禁止、哪些结论尚无运行证据；
5. 给出最小改动计划和验证计划。
```

## 第二阶段：代码适配

```text
按已确认的差异计划实施：
- 不修改原始数据；
- 所有路径改为相对路径或命令行参数；
- 固定随机种子；
- 将参数集中到配置或 CLI；
- 输出写入 artifacts/<课程>/<实验>/；
- 为关键算法添加至少 3 个边界测试；
- 运行测试与小样例；
- 记录完整命令、环境和结果。

不得编造模型指标、运行日志、图像或截图。
```

## 第三阶段：报告草稿

```text
根据本次实际运行产物生成实验报告草稿。
报告至少包含：目的、环境、数据、原理、流程、关键代码说明、参数、结果、误差/失败案例、结论。
每个数字都要能追溯到 artifacts 中的文件或日志。
对尚需本人填写的课程信息、截图、感想和答辩说明使用明确的 TODO，不得擅自杜撰。
```

## 第四阶段：验收前审计

```text
扮演严格助教，对本次实验做验收审计：
1. 随机抽查 5 个代码路径和 5 个报告结论；
2. 检查数据泄漏、训练测试混用、指标定义、随机性和不可复现路径；
3. 生成 10 个可能的口头提问及简明答案；
4. 标出本人必须真正理解的 5 个核心点；
5. 不通过的问题按严重程度排序并修复。
```

## 禁止 Codex 做的事

- 直接把历史学生报告改名；
- 用“看起来合理”的数字填空；
- 未运行就声称测试通过；
- 把低置信度预制题型说成老师原题；
- 在主分支一次性大改而不保留可回退路径。
