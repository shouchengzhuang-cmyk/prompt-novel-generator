# Codex 适配手册：从老师要求到最终报告

## 总原则

> 先确定老师要看的最终结果，再写代码；先让结果可追溯，再写报告。

算法能跑只是中途状态。真正完成的标志是：要求、代码、表格、图像、日志、结论和报告能一一对应。

## 第一阶段：收到作业当天

把老师通知、附件、数据和模板原样放入本次目录的 `teacher/`，然后使用：

```text
你正在适配河北工业大学人工智能专业的一次正式课程实验。

先做要求取证，禁止直接改代码或写报告：
1. 逐页阅读老师原始要求、评分点、数据说明和模板；
2. 提取所有显式交付物：代码、表、图、截图、视频、日志、模型、报告章节；
3. 提取所有隐式约束：指定库、禁止库、数据划分、命名、参数数量、图像数量、提交格式；
4. 阅读 docs/evidence-matrix.md 和 reporting/contracts.json；
5. 列出“正式要求 vs 最接近历史合同”的差异；
6. 新建或修订本次结果合同；
7. 对每个评分点给出对应的产物 ID、文件路径和验证方式。

输出：requirements-matrix.md 和修订后的合同草案。不要生成最终报告。
```

## 第二阶段：初始化本次工作区

```bash
python scripts/init_assignment.py \
  --course "课程名" \
  --experiment "实验名" \
  --contract 合同ID \
  --output work/本次实验
```

要求：

- 原始数据只读；
- 所有产物写入本次 `artifacts/`；
- 路径必须相对；
- 不修改其他课程目录；
- 不覆盖历史运行。

## 第三阶段：代码适配和结果设计

```text
按 requirements-matrix.md 和本次结果合同实施。

必须做到：
- 参数集中到配置或 CLI；
- 固定随机种子，并允许多随机种子跑批；
- 每次运行记录命令、时间、环境和 commit；
- 指标保存为 JSON/CSV，不只打印控制台；
- 逐样本预测、逐迭代轨迹或逐参数结果必须可导出；
- 图表由脚本生成，标题、坐标、图例和单位完整；
- 失败样例单独保存；
- 结果文件名稳定，可由报告生成器引用；
- 关键算法至少有 3 个边界测试；
- 不得编造模型指标、运行日志、图像或截图。
```

## 第四阶段：批量跑参

对参数实验优先生成单一长表：

```text
run_id,seed,model,parameter_1,parameter_2,train_metric,val_metric,test_metric,runtime,status
```

然后由同一份表生成：

- 最终汇总表；
- 柱状图/折线图/热力图；
- 最优与最差配置；
- 稳定性统计；
- 报告结论。

禁止手工从五个控制台窗口抄数字。那不是实验，是给错误数据提供繁殖场。

## 第五阶段：填写结果清单

将真实运行结果写入 `result-manifest.json`：

- `metrics`：核心数字和来源；
- `tables`：CSV 路径和说明；
- `figures`：图像路径和图注；
- `artifacts`：日志、模型、预测、视频、API 响应；
- `findings`：每条结论引用证据 ID；
- `problems`：失败样例和局限；
- `commands`：可复现命令。

先运行：

```bash
python reporting/audit_artifacts.py work/.../result-manifest.json
```

合同缺项、文件不存在、指标无来源或结论无证据时，禁止进入报告阶段。

## 第六阶段：报告草稿

```bash
python reporting/build_report.py \
  work/.../result-manifest.json \
  --output work/.../实验报告草稿.md \
  --allow-warnings
```

再给 Codex：

```text
根据生成的实验报告草稿和老师正式模板完成排版映射。
不得改变指标、图表、证据 ID和实验事实。
对本人身份、个人反思、课堂信息和无法验证的内容保留 TODO。
每个结论必须能追溯到 result-manifest.json 和 artifacts/。
```

## 第七阶段：验收前审计

```text
扮演严格助教，对本次实验做最终审计：
1. 随机抽查 5 个报告数字，追溯到日志或 CSV；
2. 随机抽查 5 张图，确认由本次数据和代码生成；
3. 检查数据泄漏、训练测试混用、指标定义和随机性；
4. 检查图号、表号、标题、坐标、图例、单位；
5. 检查绝对路径、缺失文件、错误文件名和过期截图；
6. 检查老师每个评分点是否有对应证据；
7. 生成 10 个可能的口头提问及简明答案；
8. 标出本人必须真正理解的 5 个核心点；
9. 按严重程度列出问题并修复；
10. 输出最终提交清单，但不要擅自提交或合并 PR。
```

## 给未来低额度 GPT 的最小输入包

未来即使只有普通套餐，也只需提供：

1. `docs/future-gpt-context.md`；
2. 老师本次原始材料；
3. `requirements-matrix.md`；
4. 本次合同；
5. `result-manifest.json`；
6. `artifacts/`；
7. 教师 Word 模板。

这些文件足以避免重新搜索历史题型、重新理解目录和重新手抄结果。

## 禁止 Codex 做的事

- 直接把历史学生报告改名；
- 用“看起来合理”的数字填空；
- 未运行就声称测试通过；
- 把低置信度题型说成老师原题；
- 从测试集反复挑最优超参数却不说明；
- 删除失败样例营造虚假完美；
- 在主分支一次性大改；
- 未经授权提交、合并或删除远程内容。
