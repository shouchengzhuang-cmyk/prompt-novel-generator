# 软件设计与编程实践：两周课设脚手架

## 证据等级

**低。** 培养方案只确认第 5 学期集中 2 周，题目很可能按教师和届次变化。

不要提前猜业务题。先把任何课设都要用的工程底座准备好：

```text
project/
├─ README.md
├─ pyproject.toml / package.json
├─ src/
├─ tests/
├─ docs/
│  ├─ requirements.md
│  ├─ architecture.md
│  └─ api.md
├─ scripts/
├─ sample_data/
└─ artifacts/        # 不提交运行产物
```

## 开题当天的验收清单

- 逐条提取功能需求、非功能需求和禁止项；
- 把评分点映射到模块、测试和演示步骤；
- 先做最小闭环，再加界面和拓展功能；
- 所有配置、数据路径和密钥外置；
- 至少覆盖正常、边界和异常路径；
- README 给出从空环境启动的命令；
- 保存需求变更和关键设计决策；
- 准备 5 分钟稳定演示，不依赖临时联网；
- 生成一份“答辩时可能被问什么”的清单。

## Codex 开题提示词

```text
根据老师的正式课设要求，建立需求追踪矩阵：每条要求对应实现模块、测试、演示步骤和报告章节。
先提交最小工程骨架与失败测试，不要一上来堆 UI。
任何未明确的业务规则写入 docs/open-questions.md，不要自行脑补成事实。
```
